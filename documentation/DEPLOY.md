# Run and deploy

## Locally

Step by step, for macOS, Linux and Windows: [readme](../readme.md#run-it-locally-in-5-minutes).

```bash
# backend
cd code/backend
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt
pytest -q                                   # includes an end-to-end booking over MCP
uvicorn app.main:app --reload --port 8000 --env-file ../.env   # code/.env; the key in it is optional

# frontend (another terminal)
cd code/frontend && npm install && npm run dev   # http://localhost:5173
```

Or the whole stack: `cd code && cp .env.example .env` (add the key), then `docker compose up --build`
(frontend on 5173, backend on 8000).

The agents run on **OpenAI** when `OPENAI_API_KEY` is set (`OPENAI_MODEL`, default `gpt-5-mini`): the booking agent,
owner edits, and the verifier that checks each held booking before you approve. Claude is an alternative: set
`ANTHROPIC_API_KEY` without an OpenAI key, or `LLM_PROVIDER=claude`. Without any key everything still runs: a
scripted planner walks the same MCP tools, owner edits fall back to simple rules ("add sauna"), a rule check gives the
second opinion, and the header shows **Offline mode**.

### Point any agent at the Hive

The MCP endpoint is `http://localhost:8000/mcp/` (Streamable HTTP), also listed in `/.well-known/hive.json`. Add it
as a custom connector in Claude and ask: *"Find me a dog-friendly hotel near Basel SBB under CHF 200 for next
weekend and book it."*

## What is live, and who can change it

| What | URL | Deploys | Who can change it |
| --- | --- | --- | --- |
| Frontend | https://reactbias.github.io/Adobee-Hive/ | GitHub Actions on push to `main` | Anyone with write access to the repo |
| Backend | https://adobee-hive.onrender.com (`/api/health`, `/docs`, `/mcp/`) | Render auto-deploy on push to `main` | Ask the repository owner ([Render dashboard](https://dashboard.render.com)) |
| CI and deploy runs | https://github.com/reactbias/Adobee-Hive/actions | | Repo write access |

Settings that point the parts at each other (names only; values that are secret live in the dashboards, never here):

| Where | Name | Value |
| --- | --- | --- |
| GitHub repo *Settings* > *Secrets and variables* > *Actions* > *Variables* | `VITE_API_URL` | `https://adobee-hive.onrender.com` (the Pages build's **default** hub) |
| Same place | `BACKEND_URL` | `https://adobee-hive.onrender.com` (turns on the keep-warm ping) |
| Same place | `VITE_AGENT_URL` | The `adobee-agent` service's URL. Optional: unset, the app uses the hub's own agent. Unset it and re-run the deploy to fall back |
| Render > `adobee-agent` > *Environment* | `OPENAI_API_KEY` | Secret, set in Render only. `render.yaml` defines this second service, and a Blueprint sync creates it |
| Render > `adobee-hive` > *Environment* | `OPENAI_API_KEY` | Secret, set in Render only |
| Same place | `OWNER_EDIT_TOKEN`, `DEMO_RESET_TOKEN` | Generated by Render; shared with the team in person |

`VITE_API_URL` is the hub a visitor talks to **before** they pick one, so after changing it re-run *Deploy
frontend (GitHub Pages)* in Actions. It is no longer the only hub the build can reach: picking a Hive in the
finder stores that hub's base URL for the tab and `api.ts` resolves its base per call, so a pick really moves the
app. One limit no header can lift — the Pages site is HTTPS, and a browser will not let an HTTPS page call an
`http://` hub, so the finder refuses such a hub with that reason instead of appearing to switch. A LAN demo where
every hub is plain HTTP is unaffected: the page is served over HTTP too.

### What the deployed backend deliberately does not have

`render.yaml` sets five environment variables and no more, so on https://adobee-hive.onrender.com:

| Unset | What that means there |
| --- | --- |
| `HIVE_PEER_URLS` | no peers, so a search from this hub stays local whatever reach a person chooses, and the node view draws one hub |
| `ADMIN_TOKEN`, `ADMIN_PASSWORD` | administration is **disabled**, not open: every admin write answers 503 and the panel has nothing to sign in to. Set `ADMIN_PASSWORD` in the Render dashboard to turn it on |
| `ADMISSION_POLICY` | falls back to `vetted`, so an application through `POST /api/hub/register` waits for a person, who has no panel to read it in until the line above is done |
| `HIVE_HUB_ID`, `HIVE_NAME` | the hub calls itself `local` and "Adobee Hive (Basel)" to anyone who asks |

None of that is a bug; it is what one free instance with no second hub can honestly be. The full list of gaps is
[LIMITS.md](LIMITS.md).

**Cost:** GitHub Pages and Render's free plan cost nothing. The only running cost is OpenAI usage, capped by the
limits in [Cost guard](#cost-guard-for-the-demo-key).

## Free hosting: GitHub Pages + Render (the hackathon setup)

Browser only, no local terminal. Every push to `main` redeploys both parts.

| Part | Service | Trigger | Config |
| --- | --- | --- | --- |
| Frontend | GitHub Pages, `https://<owner>.github.io/<repo>/` | Push to `main` under `code/frontend/` | `.github/workflows/deploy-frontend-pages.yml` |
| Backend | Render free web service from `code/backend/Dockerfile` | Render watches `main` | `render.yaml` |
| LLM key | `OPENAI_API_KEY`, entered in the Render dashboard only | Set once | Never in the repo |
| Data | Render free Postgres `adobee-hive-db`, `DATABASE_URL` wired in by the Blueprint | Created with the Blueprint | `render.yaml` |
| Keep-warm | Health ping every 10 minutes | GitHub Actions cron | `.github/workflows/keep-backend-warm.yml` |

One-time setup, about 10 minutes:

1. Render: *New* > *Blueprint*, connect this repo, branch `main`. Render reads `render.yaml`, asks for
   `OPENAI_API_KEY` (paste it there, nowhere else) and generates the owner and demo tokens (find them under the
   service's *Environment*). Copy the service URL, e.g. `https://adobee-hive.onrender.com`.
2. GitHub repo *Settings* > *Pages*: source *GitHub Actions*.
3. GitHub repo *Settings* > *Secrets and variables* > *Actions* > *Variables*: `VITE_API_URL` and `BACKEND_URL`,
   both set to the Render URL (no trailing slash). Then re-run *Deploy frontend (GitHub Pages)*.

Things to know about the free tier:

- **Cold start.** A free Render service sleeps after 15 idle minutes and needs about a minute to wake. The
  keep-warm workflow pings `/api/health` every 10 minutes while `BACKEND_URL` is set (GitHub may delay scheduled
  runs by a few minutes). Delete the workflow or the variable after the event.
- **Data persists in Postgres.** The free disk is ephemeral, so with `DATABASE_URL` set the backend keeps the
  DuckDB file as one snapshot row in Postgres: restored on boot, saved in the background after every write (bursts
  coalesce into one save, the last one is flushed on shutdown). Without `DATABASE_URL` each deploy starts from the
  seed. If Postgres is unreachable at boot the backend logs it, runs on the seed and does not save until the next
  deploy, so the real snapshot is never overwritten. `/api/demo/reset` still wipes everything, including the snapshot.
  A free Render Postgres expires 30 days after creation; Neon or Supabase work the same way via `DATABASE_URL`.
- **Postgres missing?** If the service was created by hand rather than from the Blueprint: Render *New* >
  *Postgres*, plan *Free*, region *Frankfurt*; then copy its *Internal Database URL* into the web service's
  *Environment* as `DATABASE_URL` and save (Render redeploys).
- **Sub-path.** Pages serves the site under `/<repo>/`. The workflow sets `VITE_BASE` for that (assets and
  images load from it), and `404.html` is a copy of `index.html` so old links like `/agent` still load the one page.

## Cost guard for the demo key

On OpenAI every call uses `OPENAI_MODEL` (default `gpt-5-mini`) at low reasoning effort with `store=false`. On
Claude the booking agent uses `CLAUDE_MODEL` with prompt caching and owner edits use `CLAUDE_FAST_MODEL`.
`AGENT_MAX_TURNS` caps each agent run. Calls that may reach a model are limited to `LLM_CALLS_PER_CLIENT_HOUR` (30)
per client and `LLM_CALLS_TOTAL_HOUR` (300) in total. If the model fails, the agent finishes the run with the offline
planner and says so, owner edits use the rules, and the rule check gives the second opinion.
